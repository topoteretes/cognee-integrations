#### 0.7.0

- feat(n8n): add the **Cognee Memory** sub-node (`cogneeMemory`) for the AI Agent's Memory port, built on `@n8n/ai-node-sdk` (`supplyMemory`). Loads the last N Q&A pairs of a Cognee session from `GET /api/v1/sessions/{id}` and stores every agent turn as a `qa` entry via `POST /api/v1/remember/entry`, so the conversation survives restarts and is readable from any Cognee client. Session entries stay in the session cache, separate from a dataset's knowledge graph. Parameters: Session ID, Dataset Name, Window Size (max 20). Works with the Chat Memory Manager node for Get Many Messages and Insert Messages; every message is written even when it has no counterpart, so nothing is dropped. The operations that wipe memory first (Delete Messages, Insert with Override All Messages) raise an explanatory error because Cognee has no per-session clear endpoint yet.
- fix(n8n): the Cognee Memory sub-node no longer pads a single message into a fake Q&A pair. Messages inserted one at a time through the Chat Memory Manager are stored half-filled, with only the side they belong to, and system/tool messages keep their role in the entry's context field, so a batch of inserts reads back as exactly the messages inserted. Also validates the write response, because `POST /api/v1/remember/entry` answers 200 with `status: "errored"` when nothing was stored.
- feat(n8n): the sub-node gains a **Dataset ID** option, required to attribute a session to a dataset shared with you; writes get a longer timeout than reads, since a write also indexes.
- fix(n8n): align the sub-node's codex metadata with n8n's own memory nodes (`categories: ['AI']`, `AI: ['Memory']`).
- docs(n8n): correct the Cognee Memory sub-node docs — sessions are stored separately from a dataset's knowledge graph and session entries do not become graph nodes on their own. Searching a whole conversation is Memory → Recall with the Session ID and session scope; knowledge the agent should search belongs on the agent's Tool port.
- chore(n8n): declare `n8n.aiNodeSdkVersion: 1` and the `@n8n/ai-node-sdk` peer dependency; the sub-node requires n8n ≥ 2.16. Version 0.7.0.

#### 0.6.0

All operations now target Cognee's `/api/v1` API, served by Cognee Cloud tenants and self-hosted servers alike. The legacy `/api/add_text`, `/api/cognify` and `/api/search` routes are no longer served by Cognee, so 0.5.x installs need this update to keep working.
